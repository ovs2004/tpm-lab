# Свои программы поверх simulator

`tpm2-tools` уже умеют discovery, PCR, подпись и seal. Дальше имеет
смысл не добавлять новые команды в shell, а вызывать TPM из своего
кода. Ниже только то, что можно собрать на текущем Docker-стенде,
без VM и без отдельного криптопротокола.

Оба simulator при этом остаются сменными: код получает TCTI из
окружения, `swtpm:...` или `mssim:...`.

## Свой модуль, не обёртка над CLI

Небольшой модуль на Python, четыре функции:

* `random_bytes(n)`;
* `extend_pcr(index, data)` — возвращает новый digest;
* `sign(message)` и проверка подписи;
* `seal(secret, pcr_index)` / `unseal(...)`.

Внутри это вызовы TPM2-TSS, не `subprocess` на `tpm2_sign`. На Ubuntu
24.04 для этого подходит `tpm2-pytss`: тот же ESAPI, которым
пользуется `tpm2-tools`, но сценарий написан у нас. Сравнение ESAPI и
FAPI сюда не входит. Это отдельный трек,
[тот же сценарий двумя API](fapi-esapi-later.md).

Проверка модуля — те же утверждения, что уже есть у runner:

* digest после Extend равен локальному SHA-256;
* чужое сообщение не проходит проверку, код `0x2DB`;
* после Extend тот же sealed object не открывается, код `0x99D`.

Если модуль проходит это на обоих TCTI, он не привязан ни к
`tpm2-tools`, ни к одному simulator.

## Две криптопроверки, которые tools сами не делают

Преподавательская криптография здесь — не новый алгоритм, а сверка
того, что посчитал TPM, с обычной библиотекой снаружи.

Первая: хеш одних и тех же байт через `TPM2_Hash` и через
`hashlib.sha256`. Digest должен совпасть. Так видно, что TPM в этой
роли обычная хеш-функция с тем же SHA-256, а не отдельная «tpm-хеш»
с другим результатом.

Вторая: подпись снимается в TPM, открытый ключ вытаскивается наружу,
проверку делает OpenSSL, не `tpm2_verifysignature`. Подпись должна
быть обычной RSA-SHA256. Испорченное сообщение OpenSSL тоже
отклоняет. Тогда `0x2DB` из прошлого прогона — не особенность
`tpm2-tools`, а нормальная проверка подписи.

Обе программы короткие, данные учебные, секрет в лог не пишется.

## Чего в этот заход не берём

Свой AES, свой протокол вроде TLS, импорт внешнего HMAC-ключа и
Quote. Quote в требованиях и так optional Demo 6, его логично трогать
после модуля и двух сверок, не вместо них.

Resource manager и `/dev/tpm0` тоже не часть этого шага. Модуль
ходит в тот же сокет, что и текущий runner.
