# ADR-002: Виртуализированный Linux как guest-среда

## Status

Proposed — требует review Student A и последующего выбора совместимого hypervisor и Linux distribution.

## Context

Основные TPM 2.0 utilities, `tpm2-tools`, способы подключения программного TPM и учебные примеры наиболее естественно доступны в Linux. Host-средой проекта является macOS на Apple Silicon/ARM64. Установка и эксперименты непосредственно на host могут смешать платформенные ограничения с поведением TPM и затруднить воспроизводимость или очистку окружения.

## Decision

Размещать будущую TPM-лабораторию в ARM64 Linux virtual machine на Apple Silicon host. Linux VM будет изолированной guest-средой для TPM tooling и взаимодействия с `swtpm`; конкретные hypervisor, distribution, версии и схема подключения виртуального TPM будут определены в следующей спецификации.

## Rationale

- Linux предоставляет ожидаемую среду для TPM 2.0 toolchain и документации.
- VM изолирует лабораторные изменения от macOS host и позволяет воспроизводить окружение.
- Разделение host и guest создает ясную архитектурную границу для диагностики.
- ARM64 guest использует возможности аппаратной виртуализации без обязательной x86_64-эмуляции.

## Alternatives considered

- **Запуск tooling непосредственно в macOS:** меньше инфраструктуры, но ниже предсказуемость поддержки и слабее изоляция.
- **Физическая Linux-машина:** реалистичная среда, но требует отдельного hardware и снижает доступность проекта.
- **Linux container без VM:** легче VM, но не создает полноценную guest boundary и может усложнить моделирование подключения TPM device.
- **x86_64 Linux через эмуляцию:** может расширить выбор готовых образов, но добавляет overhead и риск несовместимости.

## Consequences

- Понадобятся воспроизводимые параметры VM, сетевой и storage scope, а также lifecycle-инструкции.
- Необходимо проверить ARM64 Linux image и доступность всех пакетов.
- Интеграция VM с `swtpm` должна быть отдельно спроектирована и протестирована.
- Результаты внутри VM нельзя автоматически считать эквивалентными поведению физического Linux host с hardware TPM.

## Limitations

- ADR не выбирает hypervisor, Linux distribution, VM image или resource sizing.
- Решение не подтверждает, что конкретный способ подключения `swtpm` поддерживается выбранным hypervisor.
- VM добавляет слой абстракции и не моделирует все свойства physical hardware, boot chain или platform firmware.
