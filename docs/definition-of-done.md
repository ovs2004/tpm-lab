# Definition of Done

Definition of Done (DoD) — это проверяемые условия завершения. Формулировка «почти готово» не считается выполнением.

## Task DoD

Task считается `Done`, только если одновременно выполнены все условия:

- acceptance criteria определены до приёмки;
- implementation или research завершены;
- результат протестирован там, где это применимо;
- связанная документация обновлена;
- второй студент выполнил review;
- demo evidence сохранено, если задача относится к демонстрации;
- результат соответствует описанию задачи и acceptance criteria;
- код, конфигурация или документация сохранены в ожидаемом месте;
- результат проверен исполнителем на чистом, воспроизводимом сценарии;
- связанные automated tests проходят; если тестов нет, записаны ручные шаги проверки и фактический результат;
- нет известных ошибок уровня blocker или critical;
- в задаче есть краткое описание результата, команды проверки и ссылка на доказательство;
- изменения прошли Review другим участником;
- документация обновлена, если изменились запуск, API, архитектура или пользовательский сценарий;
- секреты, private keys и персональные данные не добавлены в репозиторий или логи;
- задача перемещена в `Done` только после выполнения всех пунктов.

## Sprint DoD

Sprint считается завершённым, только если:

- Sprint Goal явно оценён как достигнутый или не достигнутый;
- planned и completed tasks записаны раздельно;
- demo/review подготовлен;
- риски обновлены;
- следующий Sprint спланирован;
- все задачи Sprint либо соответствуют Task DoD, либо явно перенесены в Backlog с причиной;
- Sprint goal достигнута и подтверждена проверяемым результатом;
- запланированная демонстрация запускается по документированным шагам;
- команда провела Review результата и исправила blocker/critical defects;
- README и документы Sprint отражают фактическое состояние, а не планы;
- GitHub Project, issue status, assignee, labels и milestone актуальны;
- записаны итоги: что сделано, что не сделано, известные ограничения и следующий шаг.

Незавершённая задача не получает статус `Done` ради закрытия Sprint.

## MVP DoD

MVP считается готовым, только если:

- environment воспроизводится по документации;
- discovery demo проходит;
- PCR demo проходит;
- signing demo проходит;
- sealing demo проходит;
- автоматические проверки подтверждают реальные success и expected failure;
- доступен единый entry point или runner;
- другой человек воспроизводит MVP по документации;
- обязательные Demo 1–4 из `demo-roadmap.md` проходят последовательно;
- используется реальный `swtpm`, подключённый к виртуальной машине как TPM 2.0;
- TPM requests выполняются во время демонстрации, без fake output и заранее записанных ответов;
- создание и использование ключа, signing/verification, PCR read/extend и sealing/unsealing работают по документированным сценариям;
- в Demo 4 после реального изменения PCR возникает настоящий policy failure, секрет не раскрывается;
- Demo 5 выполняет эквивалентную security-relevant операцию через FAPI и ESAPI и сравнивает наблюдаемое поведение;
- установка и запуск воспроизводятся по документации на поддерживаемой среде;
- все MVP tests и проверки проходят, отсутствуют blocker/critical defects;
- ограничения и границы доверия описаны: что является реальным, что эмулируется и что не входит в MVP;
- Demo 6 Attestation/Quote не является обязательным условием MVP.

## Final DoD

Final считается готовым, только если:

- сравнение FAPI/ESAPI завершено;
- tests завершены;
- failures обрабатываются явно;
- документация приведена в финальное состояние;
- финальная демонстрация подготовлена;
- оба студента могут объяснить архитектуру;
- выполнены Task DoD, Sprint DoD и MVP DoD;
- обязательные демонстрации повторно пройдены по финальной документации;
- архитектура, threat model, ограничения и принятые решения согласованы с фактической реализацией;
- automated tests и финальный manual smoke test проходят в чистой среде;
- нет открытых blocker, critical или необъяснённых security defects;
- все зависимости и команды запуска зафиксированы, секреты отсутствуют;
- GitHub Project полностью актуален: завершённые задачи находятся в `Done`, остальные явно закрыты или вынесены за scope;
- подготовлены финальная защита, короткий сценарий демонстрации и ответы на ожидаемые вопросы;
- команда может объяснить происхождение каждого показанного результата и воспроизвести его без скрытых ручных подмен.
