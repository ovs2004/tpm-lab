# Дальше: Кузнечик внутри TPM

Статус: план. В Sprint 04 это не сделано.

Сейчас блок Кузнечика считает `src/tpm_lab/kuznyechik.py`. TPM только выдаёт ключ через GetRandom и отдаёт его по PCR. Это не то же самое, что AES и Camellia.

## Где живут AES и Camellia

```text
tpm2_getcap / EncryptDecrypt
  -> TPM2-TSS
    -> swtpm
      -> libtpms
```

AES имеет номер `0x0006`, Camellia — `0x0026`. Оба есть в реестре алгоритмов TCG. `libtpms` вызывает их из OpenSSL и объявляет в `tpm2_getcap algorithms`. Команда шифрования выполняется внутри `swtpm`.

Кузнечика в реестре TCG нет. В обычном OpenSSL его тоже нет. Поэтому в текущем `swtpm` такой команды нет.

## Что сделать

Патч `libtpms` и свой Docker-образ со `swtpm`, собранным против этого патча.

1. В том же переключателе, где выбираются AES и Camellia (`TpmProfile.h`, `CryptSym`), добавить экспериментальный номер алгоритма. Это не номер TCG. На защите это называется прямо.
2. Подставить блочную функцию с ключом 256 бит и блоком 16 байт. Контрольный вектор тот же, что уже сошёлся в Sprint 04: `7f679d90bebc24305a468d42b9d4edcd`.
3. Пересобрать `libtpms`, затем `swtpm`.
4. Проверить два факта: номер виден в `tpm2_getcap algorithms`; один блок через `TPM2_EncryptDecrypt` совпадает с Python-вектором.
5. Имя `kuznyechik` в тексте `getcap` появится только после правки таблицы имён в `tpm2-tss`. На первом показе достаточно номера.

FAPI-профиль и гостевой `/dev/tpmrm0` в этот заход не входят. Сначала сокет и одна команда `EncryptDecrypt`.

Seal из Sprint 04 остаётся отдельным результатом: там шифр и ключ снаружи TPM, ключ только хранится.
